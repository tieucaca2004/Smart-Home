# Tiểu Home — mobile app (Flutter)

Android + iOS client for the Tiểu Home Hub. The app talks **only to the Hub's
REST API** (see the root `README.md`); it never contacts a device vendor's
cloud and holds no vendor credentials. Its models and screens are
protocol-neutral, so devices from any adapter the Hub gains later (Matter,
Zigbee, MQTT, IR, RF, ...) show up without app changes.

## Status: Sprint 1

- **Thiết bị** — device list from `GET /api/devices`: name, online/offline,
  category, protocol; loading, empty and error states with retry; pull to
  refresh.
- **Device detail** — id, category, online state, protocol/source, and the
  device's commands/statuses from `GET /api/devices/:id/capabilities`.
  Read-only: there are no command controls yet.
- No authentication, storage, scenes or automation (not in scope yet).

## Layout

```
lib/
  main.dart, app.dart          entry point, MaterialApp
  config/hub_config.dart       Hub base URL (--dart-define) + per-platform default
  data/                        HubApiClient (the only code that does HTTP), HubApiException
  models/                      Device, DeviceCapabilities — parse the Hub's JSON
  core/                        LoadController (loading/success/failure), error wording, state widgets
  features/devices/            list screen, detail screen, online badge
test/                          model, client, controller, config and widget tests
```

UI code never imports `package:http`: screens depend on `HubApiClient`, which
turns every failure into a `HubApiException`. The only third-party package is
`http`.

## Set up the platform projects (once)

This folder holds the Dart sources; the `android/` and `ios/` platform
projects are generated by Flutter (Flutter 3.32+ / Dart 3.8+ required). From
`mobile/`:

```bash
flutter create --empty --platforms=android,ios --org com.tieuhome --project-name tieu_home .
git status            # lib/, test/ and pubspec.yaml must show no changes
flutter pub get
```

`flutter create` leaves existing files alone; if it did overwrite one of ours,
restore it with `git checkout -- <file>`.

Then make two edits, because the Hub speaks plain HTTP on the LAN:

**Android** — `android/app/src/main/AndroidManifest.xml`. `INTERNET` is only in
the debug/profile manifests by default, so a release build cannot reach the Hub
without it:

```xml
<uses-permission android:name="android.permission.INTERNET"/>
<application
    android:usesCleartextTraffic="true"
    ...>
```

**iOS** — `ios/Runner/Info.plist`, inside the top-level `<dict>`:

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsLocalNetworking</key>
  <true/>
</dict>
<key>NSLocalNetworkUsageDescription</key>
<string>Tiểu Home cần truy cập mạng nội bộ để kết nối với Hub.</string>
```

Once the Hub is served over HTTPS, both cleartext allowances can be removed.

## Configure the Hub address

The Hub address is a compile-time setting, `HUB_BASE_URL`:

```bash
flutter run --dart-define=HUB_BASE_URL=http://192.168.1.50:3000
```

| Where the app runs        | What to use                                                        |
| ------------------------- | ------------------------------------------------------------------ |
| Android emulator          | nothing — defaults to `http://10.0.2.2:3000` (the host's loopback) |
| iOS simulator             | nothing — defaults to `http://localhost:3000`                      |
| Physical Android / iPhone | `--dart-define=HUB_BASE_URL=http://<LAN IP of the Hub machine>:3000` |

Notes:

- Start the Hub first (`npm start` in the repo root). It listens on `PORT`
  (default 3000) on all interfaces.
- A physical phone must be on the same network as the Hub machine, and the
  machine's firewall must allow the port.
- A value without a scheme (`192.168.1.50:3000`) is treated as `http://`. An
  unusable value shows a configuration error screen instead of the app.
- In VS Code / Android Studio, put the same `--dart-define` in the run
  configuration's additional arguments.

## Develop and verify

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --debug --dart-define=HUB_BASE_URL=http://192.168.1.50:3000   # Android compile check
flutter build ios --no-codesign --dart-define=HUB_BASE_URL=http://192.168.1.50:3000   # iOS compile check (macOS only)
```

The tests use an in-memory fake Hub (`test/support/fake_hub.dart`) with
response bodies shaped like the real Hub's; they never need a running Hub. The
production UI never shows sample devices: what you see comes from the Hub.
